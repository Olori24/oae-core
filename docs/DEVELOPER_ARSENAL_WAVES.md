# OAE Developer Arsenal Waves

## Wave 1 — Quality and security
Critical-path tests, tenant isolation, auth boundaries, adversarial inputs, dependency and secret scanning.

## Wave 2 — Observability
API failures, slow requests, jobs, worker failures, provider failures, database health, AI usage/cost, correlation IDs.

## Wave 3 — Performance and capacity
Database pool behavior, queue/worker concurrency, realtime fan-out, API latency, memory, load and failure injection. Capacity claims must remain MEASURED rather than estimated.

## Wave 4 — Reusable primitives
Shared validation, errors, pagination, UI primitives, telemetry, job state, provider interfaces.

## Wave 5 — Automation
Idempotency, bounded retries, execution receipts, replay, approval gates, fail-closed worker policies.

## Wave 6 — AI engineering
Provider abstraction, structured outputs, model configuration, prompt/version tracking, cost/latency telemetry, evaluation and regression tests.

## Wave 7 — Africa/Nigeria adapters
Payment, messaging, identity, storage, currencies, regional provider boundaries. Keep regional behavior modular.

## Wave 8 — Recovery
Backup, restore rehearsal, migration replay, object storage recovery, configuration/secrets recovery.

## Wave 9 — Client delivery
Evidence-driven release notes, operator documentation, known limitations, cost model, security posture, and production verification.
