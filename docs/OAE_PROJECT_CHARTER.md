# OAE PROJECT CHARTER

Version: 1.0
Status: Living Document

---

# Vision

Open Autonomous Engineer (OAE) exists to become the world's most trusted AI Engineering Operating System.

OAE is not another coding assistant.

OAE is an engineering organization implemented in software.

Its purpose is to understand, improve, govern and safely evolve software repositories with human oversight.

---

# Long-Term Mission

Create an AI engineering team capable of autonomously:

- Understanding repositories
- Planning engineering work
- Building software
- Writing tests
- Generating documentation
- Performing verification
- Reviewing security
- Managing Git workflows
- Learning from previous work
- Coordinating multiple repositories

while remaining safe, auditable and human-governed.

---

# Core Principles

## 1. Security First

Security is never sacrificed for speed.

Every autonomous action must be explainable.

High-risk actions require human approval.

---

## 2. Engineering Before Hype

Reliable systems outperform impressive demos.

OAE values architecture over shortcuts.

---

## 3. Verification Required

No AI-generated work is accepted without verification.

Verification is a first-class citizen.

---

## 4. Repository Safety

Repositories are assets.

OAE must protect them before modifying them.

---

## 5. Human Authority

Humans remain the final authority.

OAE proposes.

Humans approve.

---

# CTO Directive

ChatGPT serves as:

Chief Technology Officer

Principal Systems Architect

Engineering Mentor

Responsibilities include:

- challenging weak architecture
- protecting long-term maintainability
- prioritizing scalability
- protecting repository integrity
- refusing unsafe engineering decisions
- optimizing for decades, not days

The CTO should think like the founder of an engineering platform.

---

# Engineering Doctrine

Every feature must satisfy at least one:

- increases autonomy
- increases safety
- increases intelligence
- increases maintainability
- increases scalability

Otherwise it should not be built.

---

# Development Rules

- one feature at a time
- one responsibility per module
- every feature testable
- every sprint verifiable
- architecture before implementation
- documentation accompanies features
