# Client Delivery Standard

A capability is not complete because its UI renders.

Delivery evidence should cover:
- authorization and tenant isolation
- validation and deterministic failures
- critical-path tests
- auditability
- migrations and recovery
- performance/capacity evidence
- accessibility and responsive behavior
- provider and cost implications
- operator guidance
- known limitations

Use IMPLEMENTED, TESTED, PUSHED, DEPLOYED, and VERIFIED IN PRODUCTION as separate states. Never use a stronger state without evidence.
