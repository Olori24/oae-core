# Mission 103: GitHub Change Synchronization\n\nMission 103 turns a local governed commit into a persistent, reviewable GitHub change set.\n\n## Lifecycle\n\nready workspace -> local governed branch -> commit -> change-set snapshot -> GitHub tree -> GitHub commit -> remote branch -> pull request\n\n## Persistence\n\nOAE records tenant and workspace ownership, source revision, local commit SHA, remote commit SHA, branch, changed files, synchronization state, and pull request metadata.\n\n## Security boundary\n\nGitHub credentials never enter repository files, Git remotes, logs, or job payloads. Synchronization uses the runtime GitHub token only at the API boundary.\n\nChanged files are bounded to 200 entries and 2 MiB per file. Repository paths and refs are validated before remote mutation.\n\n## API\n\n- POST /v1/engineering/changesets/sync\n- POST /v1/engineering/changesets/pull-request\n\nBoth remain behind tenant-scoped worker authorization and durable jobs.\n\n## Next\n\nMission 104 adds governed command execution so OAE can run approved tests, builds, type checks, linters, and security checks against the same mutable workspace before synchronization.
